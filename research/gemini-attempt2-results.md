# Gemini candidate, attempt 2: first evaluation of AI-generated code

The first execution of AI-generated migration code by GAUNTLET: one candidate, generated by the operator with
Gemini, evaluated once inside a disconnected virtual machine on 2026-11-07. It is a demonstration of the
evaluation pipeline on real AI output. **It is not a study of Gemini or of any model**: one attempt, one seed,
no pre-registered plan (see [../docs/AGENT_EVALUATION_PROTOCOL.md](../docs/AGENT_EVALUATION_PROTOCOL.md)).

## Execution environment

Gemini's code ran only inside a VirtualBox VM, never on the host.

* Ubuntu 24.04.4, 2 vCPUs, 4 GB RAM; PostgreSQL 16.15 installed in the VM with a randomly generated password.
* Before the run: the network adapter was disabled and the shared folders removed (both visible in the
  VirtualBox settings, and both checked by the evaluation script below).
* The evaluation script refused to start unless no shared folder was mounted, no default route existed and
  no outside address was reachable. Recorded: `ok: no shared folder mounted, no network reachable`.
* Before any Gemini code ran, GAUNTLET's candidate pipeline was tested on Linux with the repository's own
  trusted fixtures (`test_candidate_contract.py`, `test_candidate_sandbox.py`, `test_candidate_pg.py`,
  `test_observer_role_pg.py`, `test_step_timeout_pg.py`): **73 passed, 3 skipped**, exit code 0. This was the
  first exercise of the candidate pipeline on Linux.
* Inside the VM the candidate still ran in `process` mode as the VM user: the VM was the isolation boundary,
  not GAUNTLET.

### The finding

`C1_COMPATIBILITY` requires that a request from a live, registered old-version (v1) application instance never
fails with an undefined-column, undefined-table or NOT NULL error ([../docs/INVARIANTS.md](../docs/INVARIANTS.md)).
S05 requests `finalize` and `contract` while v1 instances are still registered and writing (fault F8 in
[../docs/FAULT_CATALOG.md](../docs/FAULT_CATALOG.md)); the expected behaviour is to refuse until v1 has drained.
The reference refuses. In Gemini's candidate, `migrator_finalize` and `migrator_contract` do not check for
registered v1 instances, and a v1 request then fails. The specific SQLSTATE is in the run record inside the VM
and was not transcribed. The minimized reproduction has two operations.

## Interpretation and limits

* One attempt, one seed: a demonstration, not an estimate of how often Gemini produces this defect.
* The failure is a compatibility violation under premature finalization. **No lost acknowledged write was
  found**: S02, S03 and the bounded race exploration passed.
* Passing the other scenarios is evidence about those schedules only.
* Whether this candidate passes GAUNTLET's conventional test suite was **not measured**: the conventional suite
  does not run external candidates in this version.
* The diagnosis is the oracle's; the code observation above is consistent with it, not a proven root cause.
